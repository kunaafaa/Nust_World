# Security review

Date: 2026-11-15. Scope: the whole repository at `09d56f9` and the fixes after it (Next.js 16 app, service worker,
reviews feature with Supabase, scripts, CI). Reviewer: Claude (overnight run), for the owner (GitHub `kunaafaa`).

## 1. What we protect (assets)

| Asset                                | Why it matters                                                                                              |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| Visitors' live location              | Where a student is on campus, right now. Must never leave the device.                                       |
| Reviewer accounts and sessions       | Supabase magic-link sessions (university email). A stolen session can post as that student.                 |
| Review content and ratings           | Public text about places. Abuse (spam, naming people, doxxing) harms people and the project.                |
| Integrity of the map                 | People rely on directions and place info. Injected or changed content could send people to the wrong place. |
| Supabase project keys                | The anon key is public by design; the `service_role` key bypasses every rule and must never be in this app. |
| Availability                         | The map must load and work offline even when an optional service (reviews, analytics) fails.                |
| Owner's reputation and data licences | ODbL / CC BY attribution, reference-only datasets that must not be published.                               |

## 2. Who might attack (attackers)

| Attacker                       | Capability                                                                        | Goal                                                |
| ------------------------------ | --------------------------------------------------------------------------------- | --------------------------------------------------- |
| Prankster with a crafted link  | Controls URL parameters of a link a student opens                                 | Script injection, fake UI, turn on debug/demo modes |
| Abusive reviewer               | Has (or borrows) a university email; a modified client; scripts with the anon key | Spam, harassment, flooding, bypassing text rules    |
| Network observer / third party | Sees requests leaving the device (analytics, CDN logs)                            | Learn location or sign-in codes                     |
| Malicious dependency           | Code in an npm package or a GitHub Action                                         | Steal secrets in CI, ship code to visitors          |
| Careless contributor           | Commits an `.env` or a service key                                                | (Accidental) key leak                               |

## 5. Privacy checks

- `e2e/privacy.spec.ts` records every request (URL, query and body) while location is on and a simulated walk follows
  a route. It fails on any campus coordinate or on a `lat`, `lng`, `coords`, `accuracy`, `heading` or `geo` field.
- Analytics events (`track`) carry only place ids, category names or nothing: `search` (the chosen place's name, never
  the typed text), `share`, `report_mistake`, `nearest`, `route_created`, `screenshot`.
- What is stored on the device: preferences (`nw-sound`, `nw-onboarded`, `nw-auto-recentre`), place ids (`nw-recent`,
  `nw-visited`, `nw-found`), the public reviews cache (`nw-reviews-cache`, public summaries only), and, with reviews
  on, Supabase's own session.

## 6. How to keep it this way

- Read URL parameters only through `src/lib/urlParams.ts`; add new ones there with a pattern or range.
- Never render user or URL text as HTML. No `dangerouslySetInnerHTML` except constant JSON-LD.
- New third-party origins must be added to `src/lib/security/headers.ts` on purpose; the e2e suite fails otherwise.
- Run `npm run check-secrets` before a release; CI does it on every push.
