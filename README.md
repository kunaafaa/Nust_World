# NUST World

A game-style, interactive 3D map of NUST (H-12, Islamabad). **Never get lost at NUST again.**
Next.js (App Router) + TypeScript, React Three Fiber, Zustand, Tailwind, Framer Motion. Built to deploy on Vercel.

## Run

```bash
npm install --legacy-peer-deps   # @vercel/analytics has an optional Remix peer that npm complains about
npm run dev                       # http://localhost:3000
npm test                          # 41 tests: projection, data merge, search, routing, snapping, placement
npm run lint && npm run typecheck
npm run build && npm start
```

URL flags: `?debug=1` · `?simulate=gate1` · `?flat=1` (2D map) · `?low=1` · `?place=<id>` · `?shots=1` (scripted-camera hook for screenshots).
Deploy: push to GitHub, import in Vercel, no env vars required. Optional: `NEXT_PUBLIC_SITE_URL` (canonical URL for sitemap/OG), `NEXT_PUBLIC_FEEDBACK_URL` (where "Suggest a correction" goes; defaults to the LinkedIn profile), `NEXT_PUBLIC_REPORT_EMAIL`.

## Data (OpenStreetMap + Overture, ODbL; terrain/canopy CC BY 4.0)

- **Runtime source:** `public/data/nust-full.geojson` (OSM; untouched copy in `data/raw/nust-full.original.geojson`) with the optional **topo merge** applied on top (see below). No Google Maps data or imagery anywhere.
- **Attribution:** the footer shows "© OpenStreetMap contributors · Overture Maps Foundation · terrain/canopy data CC BY 4.0 (per the export licence files)" and "Map data updated <date>" (the Overpass timestamp inside the file).
- **Licence of our data:** because ODbL data is merged into it, **our derived geodata (`public/data/`) is published under ODbL 1.0**. See `LICENSE-DATA.md`.
- **`src/data/landmarks.ts`** (your verified file) overrides OSM. Matching is by numeric `osmId`, never by name. `offCampus` landmarks are hidden (debug toggle shows them), the joke entry is removed, units 205–212 are drawn but not searchable, `verified: false` shows an "unverified" tag, unknown values show "Info coming soon".
- Aliases are normalised for search (Zakariya/Zakaria, Rehmat/Rahmat, Saloon/Salon, Ghazali 1/2): `src/lib/aliases.ts`.
- **Heights**, in priority order: `src/data/heights.ts` → `landmarks.ts` → OSM (`height`, `building:levels` × 3.4 m) → category default (academic 12, hostel 14, food 5, mosque 10, other 8). The source is shown in debug. A height implying more than 6 m per floor is treated as a data error and replaced by `levels × 3.4` (this fixes SEECS 30 m / 3 floors and SHS 30 m / 1 floor). They are listed in `docs/data-gaps.md`.
- **One projection** (`src/lib/geo.ts`): local tangent plane in metres, north up, +x east. Every position goes through `project()`/`unproject()`. Tests prove the round trip is under 1 cm, scene distance/bearing match haversine within 0.5 m / 0.5° for every landmark pair, and the Convocation Ground is a circle.
- Ground is flat by default. The optional terrain (Settings) is approximate: it comes from a 30 m model.

## What you see

- **Outline style 3D**: fat 1.5 px edge lines in category colours over almost transparent faces (7 % opacity), dark navy world with a soft bloom glow. The selected place brightens and pulses, everything else dims. Roof types: flat, dome, centred dome, barrel vault, gabled. Stylised landmarks: Main Office (drum, dome, six-column portico), Auditorium/RIMMS/IAEC domes, sports halls with two vaults.
- **Provisional blocks** (Razi Hostel only, today): a hostel area with no building outline in OSM gets an extruded block inset 3 m, drawn with a **dashed** outline, tagged "provisional shape", and listed in `docs/needs-osm-outline.md`. Nothing is silently dropped or invented.
- **Layered ground**: base, land use, water, plazas, parking, pitches, kerbs, roads, footpaths, markings, each with its own height, render order and polygon offset (no z-fighting). Pitch markings for football, tennis, basketball, volleyball and cricket; parking bay lines; kerbs; dashed centre lines; real roundabout rings.
- **Trees** (4 types, seeded Poisson-disc spacing 4–6 m, never on roads/paths/buildings/water/pitches, caps 6000 / 3000 / 1200 by quality) and **cars** (6 models, white/silver weighted, parked in bay rows 50–80 % full, up to 20 moving cars driving on the left at 20–30 km/h, slowing at roundabouts, lights at night, hidden when zoomed out). Placement is unit-tested.
- **UI**: title fly-over (once per session, skippable), search with chips and collision-aware labels, info card with Nearby / Navigate / Share / Report, day/night, Auto/Low/Medium/High graphics (auto-downgrades if FPS stays low), tree/car toggles, sound + haptics, 3-tip onboarding, "First day at NUST" tour, screenshot mode with Web Share, list view, deep links, PWA (offline), SEO (JSON-LD, sitemap, robots, OG image).
- **No WebGL?** `Map2D.tsx` is a flat SVG map with the same search, list and navigation. An error boundary swaps to it if the 3D scene crashes.

## Navigation and live location

A* routing runs in a web worker. Dangling footpath ends closer than 5 m to another path are snapped together (16 gaps fixed today). Directions are landmark-based ("Turn left at SEECS"). Buildings without a verified entrance route to the nearest footpath point and say **"(approximate entrance)"**.

Locate button (bottom right, safe-area aware): tap 1 asks permission and centres, tap 2 follows, dragging the map exits follow. `watchPosition` uses high accuracy, `maximumAge` 1000, `timeout` 15000, and pauses while the tab is hidden. The pulsing blue dot has a true-scale accuracy circle and a heading cone (DeviceOrientation; iOS permission is requested from the tap). Fixes implying more than 30 m/s are ignored; positions are smoothed; the dot snaps to a footpath only if accuracy < 25 m and the path is < 15 m away. Auto-reroute after 3 s more than 25 m off the path; "You have arrived" within 15 m. Handled: denied, unavailable, timeout, weak GPS (> 50 m), off campus. **Your location never leaves your device.** See `docs/field-test.md`.

`?debug=1` adds the routing graph, footprints, building ids, entrances, FPS, draw calls, instance counts, the lat/lng and scene x/z under the cursor, a ground legend, and "Copy landmark JSON" / "Copy height JSON" on every card.

## Topo merge (Overture + TopoExport), non-destructive

What it adds on top of OSM, all switchable in `data/topo-overrides.json` (or `?topo=off` in the URL for a quick before/after):

| Layer      | What                                                                                                               | Rule                       |
| ---------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------- |
| additions  | buildings over 100 m² with no OSM counterpart, drawn as **provisional** (dashed, default height, unnamed)          | rule 2                     |
| hostels    | outlines inside a named OSM hostel area, or around a named OSM hostel point, replace a provisional block           | rule 3: never guess a name |
| suppressed | exact duplicate OSM ways (unnamed copy hidden: stops z-fighting)                                                   | rule 1                     |
| flags      | OSM and Overture differ by over 3 m: OSM kept, flagged in `?debug=1` and `docs/field-checklist.md`                 | rule 4                     |
| trees      | ~6,000 real tree positions with canopy height and crown radius replace the random scatter inside the export frames | CC BY 4.0 canopy           |
| terrain    | optional heightmap from the 5 m contours, **Settings, Terrain (approximate), default OFF**                         | CC BY 4.0 EDTM, 30 m       |

- **Primary source: Overture, downloaded directly** (release `2026-10-21.0`, bbox 33.634,72.976,33.654,72.997) into `data/overture/`. pip was not available, so it was read straight from Overture's public GeoParquet with DuckDB (the same data the `overturemaps` CLI downloads). The TopoExport files in `reference/` are only used to cross-check Overture, and for contours and trees. They are left untouched.
- **Georeferencing is exact:** the exports are in UTM 43N with an unknown local origin; fitting only that origin makes them match Overture's own coordinates to a median **0.005 m (IoU 1.00)**, so the earlier "1.1° rotation" was just UTM grid convergence.
- **Google Open Buildings is excluded by default.** Overture republishes it, its records carry no licence field, and the project rule is no Google data without your sign-off. 1,452 of 2,314 Overture buildings in the bbox come from it. To include them: edit `excludeUpstream` in `data/topo-overrides.json`, then `npm run topo-merge`. Microsoft ML Buildings records declare ODbL-1.0 and are used.
- Heights are never taken from the topo data (94% of its labels are the 6.0 m default). `heights.ts`, `landmarks.ts` and `nust-full.geojson` are not modified.
- Rebuild: `npm run topo-merge` (writes `public/data/topo-*.json`, `data/topo-buildings.geojson`). Full counts and decisions: `docs/topo-merge-report.md`.
- The **toposection** (a single 1-D cross-section) stays reference only and is not used: `docs/toposection-report.md`.

## Decisions I made (so you can overrule them)

1. **Outline buildings replace solid ones**, per the brief. Faces stay at 7 % opacity so taps still pick buildings.
2. **Heights over 6 m per floor are rejected** in favour of `levels × 3.4 m` rather than shown wrong.
3. **Sound defaults to ON** ("mute default OFF"). Browsers stay silent until the first tap anyway. It is a switch in Settings.
4. **Main Office portico direction** is a stylisation: the columns are on the long side facing +z in the building's own frame, not surveyed. Domes add height above the walls. Landmark shapes marked stylised are not measurements.
5. **NSTP's glass wing / curved bay / louvered block are not modelled.** There is no photo or measurement in the data and the brief says never invent facts. Send photos or dimensions and it is a small addition in `src/scene/shapes.ts`.
6. **Feedback link** falls back to your LinkedIn profile because there is no feedback address in the data. Set `NEXT_PUBLIC_FEEDBACK_URL` to a form, issue tracker or `mailto:`.
7. **PWA icon**: `public/icon-512.png` plus the SVG. No 192 px PNG (headless Chrome refused to render that size). Chrome only needs one icon of at least 144 px to install.
8. `GLOBAL_OFFSET` exists in `src/lib/config.ts` and is **off**. Turn it on only if `npm run control-points` reports a systematic shift above 3 m.
9. The old `nust.geojson` / `nust-extras.geojson` and their fetch scripts are gone; `refresh-data` replaces them (smaller bounding box so it does not pull in neighbouring sectors).

## Known issues

- Bundle: ~556 KB gzip JavaScript + 95 KB gzip data. Fine on Wi-Fi; on slow 4G the first load can exceed 3 s. Repeat visits are instant (service worker). Splitting three.js postprocessing out of the first load is the next win.
- `THREE.Clock` deprecation warning comes from React Three Fiber itself; nothing in this repo uses it. No console errors.
- I verified rendering in headless Chrome with software GL (no GPU), so **real frame rates on a phone are not measured**. Use `?debug=1` on your phone to read FPS and draw calls, and the Graphics switch in Settings if it struggles.
- Live location was tested with `?simulate=gate1` (full pipeline), not with a real GPS. There is no gate named "Gate 1" in the data, so the simulator falls back to the first gate found (currently Gate no. 2). See `docs/field-test.md`.
- Three overlapping footprints, five buildings centred on water, and three places with no reachable path (Masjid, Swimming Pool, HBL Cricket Ground) are reported in `docs/position-audit.md`. They are OSM data issues, not hidden by the app.

## Campus edge

The campus boundary is derived from the OSM NUST university polygon (`npm run boundary` writes `data/campus-boundary.geojson`). Ground layers dissolve into the dark base 30 m beyond it, roads fade out, and thin dim "context ring" roads (OSM, ±400 m, `data/context-roads.json`) make the surroundings look intentional. `?edge=off` shows the old hard-cut look for comparison. Cleanup counts: `docs/geometry-cleanup.md` (`npm run cleanup-report`).
